# NemoWorld Luanti native client

This is a local native interface for NemoWorld spaces up to 96×64 tiles, including the Commons, districts, rooms, gardens and finite 48×48 frontier sectors. Luanti renders one space at a time. Entrances and frontier passages use the existing authoritative movement/travel routes. NemoWorld's Node service remains the authority for identity, positions, land stewardship, plot grants, placement/removal, missions, reviews and coins. The Lua mod never opens NemoWorld's SQLite database. No mission or coin store is copied into Luanti.

## Run locally

1. Start the **source checkout's** NemoWorld Node service against the database you intend to use, or a disposable database for evaluation. Do not point it at the separately installed `outputs/Lucy` database unless you expressly intend to run that installation. For a disposable instance: `LUCY_DATABASE=/absolute/path/to/disposable.sqlite PORT=3000 npm start`.
2. Set `LUANTI_BIN` to the verified engine binary, for example `.../luanti.app/Contents/MacOS/luanti`. Run `node native/run-local.mjs`. `NEMO_API` defaults to `http://127.0.0.1:3000` and the bridge accepts only a literal local HTTP origin, because it forwards an operator token; redirects are refused. Optional `NEMO_NATIVE_DATA` selects the native world directory; the default is ignored `native/.local/`. The launcher copies this game's source, creates a singlenode world, starts a loopback bridge and a loopback Luanti server, and prints both ports. Its bridge key is random for each launch and stored in the local Luanti config with mode 0600; the config is removed on a clean shutdown. This key is **not** a NemoWorld operator or runtime token.
3. Connect the Luanti 5.17.0 native client to `127.0.0.1:39333` with your normal native player login. A neutral floor is generated while the saved connection is checked; physics stay suspended until the authoritative scene arrives.
4. On first use, enter your **NemoWorld account email and password inside Luanti**. If more than one active human character is in an available space, select one; a single eligible character enters automatically. No browser, copy/paste or pairing code is required. Returning native logins automatically restore that character, including after a server/bridge restart. `/nemo_connect` opens sign-in and `/nemo_signout` forgets this computer's connection. The existing browser/code endpoints remain legacy compatibility tools, not the normal play flow. The Commons, connected regions, rooms and owned gardens can be visited through the Travel menu. The stitched global map is not rendered all at once.
5. Walk with Luanti's ordinary movement controls. Crossing a tile threshold requests one saved cardinal step from NemoWorld; the client waits for confirmation before the next step. `/nemo_move up|down|left|right` remains a precise text alternative. Select a supplied block item and right-click a node to request placement; punch a projected block to request removal. The bridge waits for NemoWorld's response before the mod changes a node. Land, distance, cooldown, grant, scope and account checks come from the existing server routes. A refused action shows the server reason in Luanti chat.

### Explore and build

Open inventory (`I`) and choose **Build and plot** or **Travel and places**. `/nemo_build` and `/nemo_travel` are keyboard alternatives. Travel plans a walk to an existing entrance, saves every step, then asks the existing travel authority to enter. A movement key cancels guided walking. Closed frontier neighbors can be explicitly opened at their gate, subject to existing expansion limits. Your own garden uses the existing home visit rule. Private-space access is still checked by NemoWorld.

Choosing a free plot now guides you to a standable spot and faces nearby clear ground. A visible outline marks its boundary. **Walk to my plot** returns you to it later. Right-click clear ground inside the plot to save a block; punch your saved blocks to remove them. A public road or shoreline reserve remains protected. The nine block tools are for frontier land; home furniture editing still uses the browser interface.

### Creative building

Open `/nemo_build`, or right-click air with a building tool. All nine sealed frontier materials (stone, wood, glass, brick, sand, grass, path, clay and slate) are supplied as free reusable tools. The inventory contains one tool per material: placing does not consume it. These are not purchasable goods, contribution coins or compute credits.

The menu opens automatically on first connection when you have no plot. Click **Use this free building plot** to confirm the selected nearby plot and its editable project purpose. It shows the authoritative plot registry and offers the existing three building blueprints. A refused placement displays its server reason in this menu, rather than only in chat; the HUD shows your tile and plot bounds. Preview a footprint, then explicitly place it. Both steps use the existing backend validation; a changed permission, occupied tile, excessive distance or budget can still refuse placement. Each operator retains the existing one-plot rule, collaboration grants, height/block limits and cooldowns. Walk to your plot's coordinates before placing blocks. AI residents build through the existing scoped runtime API and share the same saved blocks; this human sign-in screen does not grant AI credentials or move residents into your sector.

Trees, shallow water and labelled gate frames now project the server's actual terrain. Decorative geometry is a non-interactive render cache, not saved player construction. Six verified CC0 maps texture terrain and materials. This is not every asset or game available for Luanti: additional packs require licence review and an authoritative building representation before integration.

### Missions and conversation

- `/nemo_missions` lists open tasks and the **paired avatar's** active claim. `/nemo_claim TASK_ID` takes one lease. Repeating it while the lease is active returns the same claim; after release or expiry a new lease may be created. An active claim belonging to another avatar on the operator account is not exposed or usable here.
- Before `/nemo_submit DELIVERABLE_TEXT`, enter **your own** `/nemo_source URL PAGE_OR_SECTION`, `/nemo_method TEXT`, `/nemo_limitations TEXT`, and `/nemo_rights TEXT`. The mod does not insert example sources, imply that rights were checked, or certify evidence. Up to ten sources can be entered. `/nemo_evidence_reset` discards the local unsent statements. Evidence entered in Luanti is not saved across a restart or re-pair; a saved submission is in NemoWorld and can be inspected in its contribution history. The bridge accepts an identical retry for a saved submission and permits a new version after an independent reviewer requests changes.
- `/nemo_chat` reads recent direct/public messages, `/nemo_say TEXT` posts to the current world, and `/nemo_tell RESIDENT_ID TEXT` privately addresses a visible resident. Mission chatter is not surfaced by the native direct-chat command. Incoming private and nearby messages require the Node `/world?agent_id=...` response's `message_scope_agent_id` attestation; with an older Node service the bridge shows only public messages and private messages authored by the paired avatar, rather than risking exposure of another avatar's conversation.

The native server is restricted to loopback by the launcher. `secure.http_mods = nemo` grants only this mod outbound HTTP; `secure.trusted_mods` is not used. The bridge accepts only loopback requests and native endpoints require its per-launch mod key. Each pairing receives an in-memory nonce, bound to every native request; a delayed callback from a replaced pairing is refused. Native human connections accept only an active `kind: human` avatar owned by the operator session. The operator token is checked through `/me` before every action and never enters the Lua mod, Luanti world files, model input or logs. The normal launcher also remembers it in an AES-256-GCM encrypted connection cache under `NEMO_NATIVE_DATA/private/native-session`, with a separate 32-byte key. The directory is mode 0700 and files mode 0600, owned by the OS user. Encryption binds the cache to the exact local API origin. This protects the cache from other OS users and accidental plaintext exports; it does not protect against compromise of this OS account, which can read both files. The native mod handles the password transiently only to submit account sign-in to the local bridge; it never stores it. Saved access obeys the existing seven-day operator-session expiry and revocation. After ordinary expiry, sign in inside Luanti again; there is no code exchange. Tests that construct a bridge without `sessionDirectory` retain memory-only, twenty-minute connections. A fresh per-connection nonce rejects old requests after automatic return. Revoking the operator session or pausing the human avatar stops actions at the next request. AI runtime tokens are not accepted by native human sign-in; AI residents continue to use NemoWorld's existing scoped runtime API, and their approved blocks are projected into the native sector.

## Coordinate and authority map

| NemoWorld `frontier:0:0` | Luanti world |
| --- | --- |
| `x = 0…47` | `x = 0…47` |
| `y = 0…47` (southward tile row) | `z = 0…47` |
| block layer `z = 0…7` | vertical `y = 0…7` |
| terrain floor | `nemo:ground` at Luanti `y = -1` |
| finite functional boundary | existing server movement and plot bounds; obsolete native enclosure walls are removed |

The initial scene obtains one authorized `/world?view=voxel` response. Static terrain and authored scenery come from the matching project world definition only after that access check succeeds; private spaces are never projected on a refused read. The complete terrain is sent once on entry. Later refreshes omit unchanged terrain and merge the bounded 37×37 dynamic block window into the native cache. Previously loaded distant blocks are reconciled when revisited; the cache is not a second authority.

Ordinary movement uses the existing `/move` position receipt immediately, without waiting for a full scene fetch or zeroing walking velocity at every tile. Scene/participant refresh remains every five seconds and after local building. Guided movement advances its queue only after an accepted step, uses real elapsed time, and retries the same step after a 429 without changing the server throttle. A scene load clears stale native geometry and old enclosure walls; the finite server world bounds still apply. Residents outside the loaded view can appear on approach. This is not continuous streaming of all worlds at once.


## Verification

`LUANTI_BIN=... node native/luanti-controls-smoke.mjs` reproduces the physical-origin/heartbeat regression and tests native walking, preservation of jump velocity, visible unowned-placement refusal, explicit plot selection, reusable ground-click placement and punch removal against the real server and database. It invokes real engine callbacks with a synthetic player; it does not claim a GUI mouse-and-keyboard pass.

`LUANTI_BIN=... node native/luanti-onboarding-smoke.mjs` invokes this mod's real join callback
with a synthetic player in a disposable engine/world. It proves the native sign-in screen is shown,
unpaired physics are suspended and the actual engine generates a floor without a paired account.
It does not automate a real person's account sign-in.

`node --test native/bridge.test.mjs native/bridge.integration.test.mjs native/creative.integration.test.mjs native/assets.test.mjs` covers boundary mapping, local pairing, mod-key enforcement, owner validation, revocation, shared block rows, web-to-native and native-to-web visibility, authoritative crossing, mission claim ownership, reclaim after release, evidence refusal, versioned submission, private-message isolation, and reopened database persistence. `LUANTI_BIN=... node native/luanti-smoke.mjs`, `LUANTI_BIN=... node native/luanti-mission-smoke.mjs`, and `LUANTI_BIN=... node native/luanti-conversation-smoke.mjs` launch the **real pinned Luanti server** and invoke registered mod callbacks in disposable games. The probes use synthetic players; they do not automate GUI clicks, physical WASD input, or a real person's evidence review. Each deletes its temporary database and Luanti world.

Residual limits: Luanti renders one authorized space at a time, with schematic native scenery and a bounded dynamic block window; expansion of a new sector remains an explicit NemoWorld action, and this is not a deployed public server, MMO capacity claim, graphical native mission UI or a complete AI-native client. The launcher stores only the Luanti rendering world; NemoWorld remains the single durable world/mission authority.
