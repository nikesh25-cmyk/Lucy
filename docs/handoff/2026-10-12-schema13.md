You are continuing work on **NemoWorld**, a zero-dependency Node.js web application at
`/Users/nikesh/Documents/Codex/2026-10-11/i-ve-prepared-automatic-mac-setup/outputs/Lucy`.
Read `README.md`, `docs/ARCHITECTURE.md`, `docs/START_HERE.md` and this file first.

NemoWorld is a persistent shared world where human players and independently-credentialed AI
agents have characters, homes and building rights, wrapped around a country-research/evidence
layer (UN M49 countries, SDG targets, World Bank WDI series) with source-scoped research
proposals, independent review and recorded adoption. The stack is deliberately minimal:
`node:http`, `node:sqlite`, and locally vendored assets. **There are no npm dependencies.**

| Check | Command | Result |

`npm test` is the authority for any count you quote. `npm run e2e` is the release-acceptance
gate: it starts a real server in public mode with a setup code and drives register → character →
move → land stewardship → block build → scoped runtime credential → claim → submit → independent
review → coin award, asserting real HTTP status codes. Keep both green.

The schema is `user_version = 13`. Migrations are additive and idempotent (no numbered runner):
`src/database.js` holds the version guard and the ALTER/probe block; `src/recovery.js` holds the
accepted-version list and per-version validation. **If you add a schema change, update both, and
bump the hard-coded version assertions in `tests/`.**

### Remaining work, in priority order

1. **Restart the running server.** A `node server.js` process started before this pass is still
   listening on `127.0.0.1:3000` and is serving the **old** code. Kill and restart it to exercise
   the new features. (The e2e harness never touches `data/` or port 3000.)
2. **Decide the repository license.** There is **no root `LICENSE` file** and no `license` field
   in `package.json`. The content layer records this honestly rather than inventing a license.
   This is a legal decision for the owner, not an engineering one — do not add a license
   unilaterally.
3. **`POST /api/v1/agents/:id/move` does not exist and returns 404.** The documented operator form
   is `POST /api/v1/move` with `{agent_id, direction}` (see `docs/API.md` §4), and the dynamic
   route regex in `server.js` intentionally covers only
   `travel|build|home|heartbeat|posture|look|climb`. Either document this as intentional or add
   the route; the e2e harness deliberately records it as a note rather than an assertion.
4. **`app.js` still carries its own mayor sheet-number preload list and `state.buildKind`
   default** — the last duplicate of content-layer truth. It is pinned against content by
   `tests/content.test.js` so it cannot drift silently, but wiring it to `src/content.js` would
   remove the copy outright.
5. **Vertical physics** (falling, jumping, acceleration, air control): genuinely deferred. The
   researched design insists a fixed-`dt` simulation tick exists first, and that the existing
   integer-tile contract (`world.js walkable/move`, portal adjacency, the ≤6 build range, and a
   large fraction of the test suite) must not be broken to get float positions. See the risks
   section of this pass's elevation research before attempting it.
6. **Chunk-rendering phase 3** (batch-level selective rebuild for one-block edits) was left
   conditional — it only pays off in heavy frontier build sessions. Phases 4–5 (server terrain
   window; greedy meshing with merged `BufferGeometry`) were recommended **against**.
7. **Real-pilot prerequisites are not code** and cannot be completed by an AI alone: real mission
   owners, beneficiaries, licensed inputs, qualified independent reviewers and acceptance rubrics;
   a hosting account and provisioned HTTPS service with persistent storage; and a benchmark of
   ~10,000 simultaneous residents. See `ROADMAP.md`.
8. **Browser/WebGL verification is still manual.** CI runs `npm run check` and `npm test` only;
   the Chromium checks described in `docs/VERIFICATION.md` are one-off, and the new e2e harness is
   HTTP-only. A checked-in browser harness is the largest remaining verification gap.

### Hard boundaries — do not cross without an explicit decision

- **Do not break the invariant that the server is the authority.** UI previews and model output
  are requests. `src/elevation.js`'s `allowAuthoredStepUp` default (authored blocks are walls) is
  load-bearing for existing tests — do not "simplify" it away.
- **Do not add npm dependencies.** The zero-dependency property is a deliberate feature and is
  relied on by the vendored-bundle hash tests.
- **Do not modify `assets/vendor/three-voxel.js` or its manifest** — it is pinned by hash, and
  `tests/voxel-world.test.js` verifies it. Same for `assets/manifest.json`,
  `assets/mayors/manifest.json` and `content/content-manifest.json` (re-seal with
  `node scripts/seal-content.mjs`, never hand-edit).
- **Do not implement commerce, land sales, transfers, resale, arbitrary user scripts, or
  Minecraft/decompiled content.** These are explicitly out of scope in `docs/LAND_WORLD.md`,
  `ROADMAP.md` and `docs/VOXEL_ENGINE_REUSE.md`. An open-source decompiler's license does not
  license the game code or assets it produces.
- **Keep `data/` private** and never let a test or harness write to it — tests must use temp
  databases.
- **After any change, run `npm run check`, `npm test` and `npm run e2e`.** Do not mark work
  complete with a red suite.

### How this codebase is easiest to work in

- Route tables are hand-maintained in `server.js` (`files`, `gets`, `writes`, `dynamic`). Adding a
  route in one place and not another silently 404s or 401s.
- Many invariants are enforced in **SQLite triggers and unique indexes**, not only in JS — read
  `src/database.js`, `src/frontier.js` and `src/placement-policy.js` before assuming a JS check is
  the protection.
- Tests are hermetic (`mkdtemp` temp databases, `listen(0)`), so they are safe to run in parallel
  with the dev server.
- `npm run e2e` accepts `LUCY_E2E_KEEP=1` to keep its temporary workspace for debugging.
