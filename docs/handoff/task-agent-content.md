Branch `task-agent-content`, worktree `w2-content`, based on `codex/final-integration` at
`1de1de3`. Slice: expand the **authored content** so a resident always has something to do, additively,
with nothing new minted and no existing definition's meaning rewritten.

## The calling objective finding

The goal asks for "more CALLING objectives where the model supports them". I did not add any, because
the model supports **two per calling and no more**, and this is measurable rather than a matter of
taste:

- Calling objective experience is a fixed five points (`src/vocations.js` `objective()` and the
  `points=5` `CHECK` on `calling_receipts`).
- The resident's shared ceiling is ten points per UTC day, enforced by the
  `calling_receipts_validate_insert` trigger (`SUM(points) … > 10` refuses) and published as
  `CALLING_POLICY.daily_experience_limit`.
- A given objective can be earned at most once per UTC day (`UNIQUE(agent_id, earned_day,
  objective_id)`).

So a third objective per calling is unreachable on the day it is offered: `today.remaining` is 0 for
it, and `current_objective` would name a step the daily limit refuses. `tests/vocations.test.js`
already asserts the invariant the extra objective would break — after the calling's own two facts,
`today.objectives.every(o => o.complete)` is true and `experience.available` is 10, for the
cultivator, explorer, steward and artisan callings.

More to pursue was added instead where the model does support it, and it credits the *same* ledger:
two new built-in **quest chains** whose four steps each need a different saved fact and which
therefore span more than one UTC day. `docs/CALLINGS.md` now states the reason in the product
documentation, so the next reader does not have to rediscover it.

## Migration, rollback and residual limits

- **Rollback** is a single `git revert` of the one commit: every change is additive, and the three
  regenerated content files are reproducible with `node scripts/seal-content.mjs`. No schema version
  was touched (`PRAGMA user_version` stays 23), no table, column, index or trigger was added, and
  no stored row is rewritten by the code path.
- **A database created before this change keeps its old enumerations.** Three `CHECK` lists are
  generated from the sealed content at `CREATE TABLE IF NOT EXISTS` time, so a world created earlier
  keeps the shorter list and would refuse the new values until the table is rebuilt:
  `journey_crops.kind` (`src/journey.js`, three crops), `frontier_blocks.type`
  (`src/frontier.js`, seven block types) and `quest_steps.source_kind`. All tests use fresh
  databases, so this cannot show up in the suite; it is the honest limit of an additive enum on
  SQLite without a schema migration. A rebuild is a schema migration and was **deliberately not
  attempted**, because schema 23 is reserved for another owner (`src/database.js`) and the brief says
  to stop and report a change that genuinely needs one. A fresh world (or a rebuild of those three
  tables) is required to use `blossom`, `grain`, `resin`, `clay` and `slate`; everything else in this
  slice — the recipes, the quest chains, the palette furniture through the storage guard — is
  unaffected because those paths read the content layer at runtime.
- **`content/THIRD_PARTY.md` was not updated** and its per-group counts (`blocks/ 7`,
  `furniture/ 27`, `crops/ 3`) are therefore now descriptive rather than current. It cannot be
  updated from this slice: every definition records its SHA-256, so editing the shared notice file
  would invalidate `license.notice_sha256` on all 98 entries, including the frozen
  `content/appearances/**` and `content/cosmetics/**`. The executable counts live in
  `tests/content.test.js`, which the file itself points at.
- **The passport's "Plant crop" dropdown still offers three kinds.** That list is a hardcoded literal
  in `app.js` (line 2225), which this slice must not touch. The game path is correct: the world
  interaction overlay derives its plant options from the sealed crops and now offers all six
  (`tests/interaction-prompt-http.test.js` asserts it). The follow-up for whoever owns `app.js` is
  one import (`import content from './src/content.js'`) and one derived options list; the browser
  already serves that module and its definition files.
- **The four new furniture types draw through the renderer's generic `prop` branch in the voxel
  scene**, which is what `rules.geometry: "prop"` records and what the existing `sculpture` and
  `pond` entries already do. Distinct bespoke geometry for them belongs in `src/voxel-world.js`,
  which the character-art and character-quality slices also touch; it was left alone deliberately.
  The pixel map does draw each of the four distinctly (`world.js` `drawObject`).
- **The authored recipes live in `src/journey.js`, not in `content/cosmetics/**`.** That directory is
  on the never-touch list for this wave, so the ladder is an authored, load-validated list in the
  journey module instead of sealed cosmetic entries. It is published in the identical recipe shape,
  it is validated once at load (`recipeDefects`), and a test proves the whole ladder is reachable
  from five garden beds. If a later wave wants them sealed with their own licence records, moving
  them into `content/cosmetics/craft-*.json` is a mechanical translation — the published shape does
  not change.
- **The written test counts in `docs/RELEASE_CHECKLIST.md` are now stale** (G2's `tests 989` and
  G5's `89 definitions`). That file records a specific integrated release and says an intentional
  count change belongs in the handoff, so it was left untouched: the numbers below are the record
  for the next release owner to fold in.
