# Browser session recovery

An expired, revoked, unknown or malformed browser session cookie is cleared when authentication returns 401. Public GET pages continue as an anonymous visitor; private reads and writes still return 401. A private garden remains private. An explicit Authorization header never falls back to visitor access and never clears an unrelated browser cookie. Other authorization failures, such as scope denial, are not downgraded.

While signed in, an authentication failure or the expired-session response header returns the browser to visitor mode. Operator account, agents, private world messages/directories, missions, history/drafts/jobs, moderation/operations, resident passport and community state are cleared from the active page. Open private dialogs and the displayed credential are closed/cleared. Public data is refreshed and the page explains that a new sign-in is required. Background refresh detects expiry; it does not continuously replace active forms during a valid session.

A browser session epoch changes on recovery, sign-out and successful sign-in. Responses from an earlier epoch are rejected before their data can update the current page. This prevents a delayed successful private read from repopulating state after sign-out. Existing server permissions still govern every request and write.

Saved database records, accounts, drafts and world positions remain intact. Signing in again restores saved drafts through the normal owned history endpoint. Unsaved edits cannot be written after authentication ends; wait for the draft-save confirmation while the session remains valid. Browser recovery does not revoke separately authorized runtime credentials or cancel server jobs; those retain their existing limits and stop controls. This is not a claim about erasing browser memory, downloads or other copies of data previously accessed.

Verification: all 147 automated tests passed at that milestone. HTTP checks cover stale-cookie public recovery, private read/write refusal, private-world boundaries, explicit-header failures and cookie isolation. The state reset clears known operator-visible fields and increments the response epoch. Actual isolated browser QA revoked a fixture session, verified private controls disappeared, signed in again and restored its saved draft. A second fixture held an already authorized history response for fifteen seconds, signed out, released that response, and verified private controls did not return while the public 248-entry country catalog remained usable. Production accounts were not created or altered for QA.
