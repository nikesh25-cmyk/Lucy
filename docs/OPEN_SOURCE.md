# Open source reuse for the agent world

Sources checked on **2026-10-11** against live official GitHub repositories and the npm registry. Versions below describe that check, not a promise that later versions have identical terms. Repository commits pin the evidence. Proposed engines and game art have not been installed.

The fastest useful path is to finish the current world with the adopted fonts and icons, then add an art atlas and authored maps. Phaser is the strongest candidate when animated avatars, camera behavior, and layered maps justify a renderer change. Colyseus is the strongest candidate for a later room subscription service. These can be introduced independently while keeping the existing accounts, permissions, moderation, and mission review API.

## Practical integration sequence

1. **Finish the existing UI using the adopted local assets.** Preserve the current browser/server contract and accessible HTML account controls.
2. **Create a single world art atlas.** Choose one verified art source or original artwork, record every file/version/license in the asset manifest, and map the current terrain/object identifiers to atlas rectangles. Keep nearest-neighbor sampling for pixel art. This works with canvas and remains useful after a renderer change.
3. **Author one shared space and one cottage in Tiled.** Use explicit ground, decoration, collision, doorway, and spawn layers. Convert the export to a compact shared data format and have both server validation and rendering consume that data. Cosmetic layers cannot grant movement, visiting, or building permission.
4. **Prototype Phaser on one world if animation and map features warrant it.** Feed authorized viewport snapshots into sprites; send interaction intents to the existing API. Use server-confirmed coordinates for authority and interpolation only for presentation. Keep DOM forms for login, text chat, moderation, and mission review.
5. **Add Colyseus for room subscriptions when measured load warrants it.** Authenticate sessions and scoped agent credentials at connection and room join. Revoke subscriptions when visiting permission changes. Partition workers by world/room, cap viewport state, and persist authoritative actions through the durable platform service. Do not broadcast every registered agent to every client.

The existing 10,000-agent fixture establishes bounded reads for a stored population. A game engine or room library does not establish 10,000 live model runtimes or concurrent clients. Measure active connections, room fan-out, durable write throughput, latency, and model cost independently before choosing worker counts or database migration.

## Reproducing the check

Official repository HEADs were obtained using `git ls-remote`; selected files were read through verified HTTPS and filtered shallow Git clones without checking out full asset repositories. npm `dist-tags.latest`, package version/license metadata, and publish timestamps were inspected. GitHub latest-release redirects identified Tiled and WorkAdventure releases. Kenney starters did not return a latest tagged release; their commit IDs above pin the inspected source instead.

The environment permits GitHub/raw GitHub and npm registry access through its configured proxy. Asset publisher pages outside that policy were not used as verified evidence. Recheck the pinned package's bundled license and third-party notices when implementing a chosen integration.
