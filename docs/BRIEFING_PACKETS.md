# Downloadable reviewed briefing packets

Every accepted gallery contribution offers a readable HTML briefing and matching JSON packet. Structured briefs include the requested decision, proposed recipient and roles, beneficiary/scope, cited findings and qualifications, alternatives, milestones, a detailed cost register and evidence still needed. Plain-text evidence receives the same source, method, review and provenance sections. Practice contributions are explicitly labeled demonstrations.

The source register preserves each submitted URL, exact supporting location and contributor-recorded publication or retrieval date. The human review record includes the reviewer, review date, mission criteria and full explanation, including any finding assessment. The packet also records the submission/version, contributor, mission/task, beneficiary, generation date, review identifier and documented platform-use count. It omits account IDs, emails, passwords, runtime credentials and idempotency keys.

`GET /api/v1/briefing?submission=<id>&format=html` or `format=json` generates a current snapshot of an accepted public gallery record. Pending, rejected and quarantined records return 404; unknown formats return 400. The selection and packet construction occur inside the existing database transaction, so an old gallery link cannot download a record that has since been quarantined. Both formats use attachment filenames including the submission ID/version and `Cache-Control: no-store`.

HTML is self-contained, has no scripts, fonts, images or automatic external requests, and escapes all contributed content. Source URLs require HTTP/HTTPS without embedded credentials. Source-number links navigate to the corresponding register entry. A restrictive content security policy applies in the file and the HTML response. Styling supports narrow screens and A4 browser printing. Downloading or opening the packet does not send a recommendation, create institutional consent or record adoption.

A packet is a snapshot rather than a signed certificate. It can be edited after downloading or become outdated after corrections/moderation. Human review remains a recorded judgment; rights statements and source-backed classifications are not converted to legal permissions or factual certification. Unknown cost rows keep the total incomplete; original decimal rows are normalized again instead of trusting a copied subtotal. Proposed recipients/roles and documented platform uses do not prove external decisions.

Verification: 152 automated tests passed. Tests cover current accepted-only delivery, refusal before review and after quarantine, private pending-record refusal, exact decimal/unknown values, source locations, metadata omission, practice labels, HTML escaping and HTTP content/disposition/cache/security headers. Actual guest-browser downloads returned both files. Their bytes were inspected; the rendered HTML retained the fictional recipient, evidence gaps and full review, and citation navigation exposed its source register. The 390px layout had no horizontal overflow. Screen rendering and print stylesheet presence were verified; physical printing and institutional receipt were not tested.

The original Blob download produced a file but its browser automation event timed out. The final implementation uses direct server attachments, and both final download events completed. QA used an isolated world; no production account or real trade recommendation was created. `LUCY_BRIEFING_FIXTURE.html` and `.json` are fictional workflow examples, not completed agricultural research.
